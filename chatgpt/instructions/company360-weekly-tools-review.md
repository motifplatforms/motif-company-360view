# Weekly research skills review (company360-weekly-tools-review)

Use this when: Review weekly discoveries and prior research failures for candidate skill, tool or workflow improvements and decide whether to adopt or defer them. Use for Company 360 or comparable Motif company deep dives requiring this research decision. Focus: Evaluate tool changes on frozen research examples.

## Deliverable and owning workbook

Working-session record → changes and operating feedback; validation register → regression evidence. For a new company, confirm equivalent workbook and tab names with the planner.

## Method

1. Start from recent failures and the dated installed skill inventory. Search official release notes, reference implementations and existing Motif assets; record actual publication URL, version, date and permissions.
2. Choose a frozen task, expected outcome and meaningful baseline. Trial a candidate on unchanged inputs and measure decision accuracy, provenance, reproducibility, time, overlap and cost. Mark untested claims as leads.
3. Adopt compatible improvements only within granted change scope and after passing regressions. Keep prior revision for rollback, explain the observed lift and update shared dependencies once. Raise new spend, external transfers or permissions for owner approval.
4. Return one result per candidate: adopt, defer or reject, with exact failure addressed, evidence link, reviewer, previous/new revision, next test and follow-up date. A review with no qualifying candidate can close as no change.

## Acceptance example

An evaluation framework with stronger marketing but no improvement on a fixed source/pack mismatch remains deferred.

## Evidence and handoff
Read the current assignment and latest founder scope. Use public desk research and sources already authorized for the project. Resolve evidence, entity, resource and observation IDs before a new search. Keep US and Canadian facts distinct. Reuse one canonical resource per publisher, edition and binary hash, with distinct observations per locator, entity, date and metric. Record inherited rows separately from newly checked or collected evidence. Use null for unavailable values and retain true zero only with a source that reports zero.

Stage additions with job ID, skill version, entity/brand, market, reporting window and basis, unit and currency, raw observation, value, evidence classification (fact/inference/assumption/unavailable), evidence ID, source edition/URL/exact locator, access date, coverage/denominator, limitation or competing evidence, proposed workbook/tab, and next action. When no source qualifies, include search terms, sources checked, access results and the decision affected. Reuse the same job key on retry. Keep separate assertions for conflicting values and identify both sources. Coordinate canonical workbook changes through the assigned publisher.

Emit an honest status receipt at handoff: queued, running, staged, in review, targeted rework, blocked or accepted; job ID, actual assignee, Eastern timestamp, evidence link, dependency, next action and blocker. Use the shared tracker when available. Count completion only against the agreed acceptance criterion.
